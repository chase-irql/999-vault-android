# Android versus desktop

`platform-parity.yaml` is the canonical feature-by-feature inventory. This document summarizes the user-visible adaptations; evidence paths are repository-relative and generated device artifacts remain ignored by policy.

| Domain | Desktop behavior | Android behavior | Why and user impact | Migration implication | Verification evidence |
|---|---|---|---|---|---|
| Navigation | A collapsible window sidebar, narrow-window menu, and tray expose every route. | Four stable bottom destinations—Archive, Listen, My Music, Search—lead to nested Downloads, Wrapped, Settings, Credits, lyrics, playlists, viewers, queue, and Now Playing. Back unwinds nested destinations and does not stop playback. | Bottom navigation preserves reachability and content width on a phone. Routes move, but none disappear. | Window geometry, sidebar collapse, and tray state do not migrate. | `NavigationTest`; `qa/artifacts/20260805-200308/device/archive-final.png` and the portrait/landscape top-level set. |
| Presentation | Dense desktop grids assume a mouse, resizable window, and keyboard. | Edge-to-edge Compose layouts use scrolling content, system insets, 48 dp controls, native IME behavior, portrait/landscape adaptation, TalkBack labels, and a compact mini-player. | Phone reachability and accessibility take priority over pixel copying. Brand colors, hierarchy, archive terminology, and credits remain. | No display preference is imported; Android accessibility settings apply immediately. | `NavigationTest::topLevelNavigationRemainsOperableAtTwoHundredPercentFontScale`; `font200-final.png`. |
| Playback authority | Electron/Web Audio owns playback inside the desktop process and uses desktop/tray integration. | One Media3 `MediaSessionService` owns one ExoPlayer; Activities use a `MediaController`. Android supplies notification, lock-screen, audio-focus, noisy-route, and media-button behavior. | Playback survives navigation and Activity recreation and participates in the operating system’s media model. | Queue/session state migrates only through account/domain data, not desktop process state. | `PlaybackServiceConnectedTest`; `now-playing-final3.png`; `now-playing-actions-final.png`; `resilience-logcat.txt`. |
| Playback controls | The desktop player exposes queue transport, seek, volume, repeat, shuffle, and output through desktop controls. | Now Playing exposes the same transport policy, seek, app volume, output status, queue, device/cloud favorite, lyrics, and download actions; hardware/system volume remains authoritative. | Controls are wrapped and scrollable instead of compressed. | No desktop audio-device selection is imported. | `PlaybackServiceConnectedTest::mediaSessionControllerExercisesTransportAndQueuePolicies`; Now Playing screenshots. |
| Catalog Next | Direct Catalog playback may advance through canonical catalog order while explicitly queued items retain priority. | The service persists an explicit playback mode. Shuffle avoids an immediate repeat; shuffle-off advances by canonical order; explicit queue priority is documented and tested. | This preserves the product’s distinctive discovery behavior without creating a second UI-owned player. | Canonical numeric IDs are required; path-only files never acquire a cloud identity by title matching. | `QueueEngineTest`; `PlaybackServiceConnectedTest`. |
| Equalizer | A fixed ten-band Web Audio equalizer is available in the desktop renderer. | Equalizer is capability-disabled with an explanation; playback never depends on it. | A safe Android audio-effect session and deterministic device-band mapping are not yet proven on the target. | Desktop EQ values are not imported. This item is explicitly deferred, not silently omitted. | Settings screenshot; `equalizer` parity entry; `known-limitations.md`. |
| Storage | Desktop downloads use ordinary Windows folder paths and folder pickers. | `VaultStorage` targets app-specific external storage or a persisted SAF document tree. Content URIs are labelled as provider locations, never fake paths; `MANAGE_EXTERNAL_STORAGE` is absent. | This follows scoped-storage and provider ownership rules. Provider permission loss becomes a recoverable transfer error. | Windows-local files are not directly imported. Users choose an Android tree if they do not want app-specific storage. | `VaultStorageTest`, connected SAF probe, `docs/decisions/0002-storage-saf.md`. |
| Transfers | Electron background tasks and tray state manage files and the server-side collection ZIP. | Durable Room jobs use user-initiated transfer jobs on API 34+ and foreground WorkManager fallback on API 26–33, with notifications, Range/ETag validation, stage ETA, streamed Zip64-safe extraction, checkpoints, and real socket cancellation. | Android may constrain timing/concurrency, but jobs expose truthful state and resume deterministically. | In-progress desktop jobs do not migrate; completed account/library state remains independent. | `DownloadFixtureIntegrationTest`, `DownloadDeviceFixtureTest`, download screenshot and cancellation log. |
| Account security | Electron `safeStorage` protects account state and desktop IPC delivers callbacks. | Android Keystore AES-256-GCM protects a rotating envelope; an exact `vault999://auth/callback` flow validates state, PKCE, one-use ticket, replay, expiry, refresh, and logout tombstones. | The browser and lifecycle differ, while token confidentiality and refresh semantics remain. | The owned account origin must be supplied outside source control; desktop tokens are never copied. | `AuthSessionManagerTest`, `SessionStoreTest`, `PkceTest`, release lint/security review. |
| Local and cloud library | Desktop presents local and account-backed library state in one window. | Device downloads/favorites/playlists/history remain usable signed out and survive logout. Cloud likes/playlists and pending/conflicted mutations are separately labelled and hidden after logout. | Android must remain useful offline without implying that local ownership is synchronized. | Only trusted canonical numeric IDs may enter future device-to-cloud migration. | `CloudLibraryRepositoryTest`, library unit tests, My Music and Settings screenshots. |
| Listening and Wrapped | Desktop aggregates listening credit and synced history. | Room journals UUID events, applies the 30-second/half-short-song rule with seek/gap rejection, syncs by set union, and renders All time/30-day/7-day coverage without invented timestamps. | Durable events tolerate process/network interruption while preserving honest coverage. | Legacy totals without timestamps contribute only where their period is known. | `ListeningTest`; Wrapped tests and `wrapped-final.png`. |
| Discord Rich Presence | Desktop IPC can publish presence to a locally running Discord client. | Not applicable. Discord account OAuth remains separate; mobile Rich Presence is not attempted. | Android has no equivalent local IPC contract for this desktop feature. | No presence state migrates. | `discord-rich-presence` parity entry. |
| Packaging | Desktop creates Windows installers and shortcuts. | Gradle produces debug/fixture/release APKs and an R8 release AAB; signing material is supplied externally. | Windows shortcuts have no Android meaning. Launcher/package installation replaces them. | No installer preference migrates. | `scripts/verify.ps1`; release output and dependency reports. |

Deferred conveniences are listed exactly in `known-limitations.md`: cover export, speculative Listen byte preloading, named bulk presets, best-audio selection, artwork-quality packages, assisted device-to-cloud playlist migration, custom cloud covers, and public playlist sharing. Android Auto, Cast, Wear OS, widgets, picture-in-picture, store rollout, iOS, and direct Windows-folder import remain outside this phone release scope.
